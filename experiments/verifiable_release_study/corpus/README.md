# Draft R0 Clean Bases

Status: exploratory design inputs; not frozen; not independently reviewed  
Confirmatory derived cases generated: **no**

## Why the bases are separate from cases

The preregistration timing rule freezes clean R0 bases, recipes, seeds, catalog,
oracle, and compatibility before registration. Mutated case archives are R1
evidence and may be generated only after registration. The constructor in
`scripts/build_r0_bases.py` has no mutation interface and emits no `cases/`
directory.

## Strata

- `S1-CONFORMANCE` uses deterministic public test-PKI material to reach parser,
  signature, identity, and provenance branches. It cannot support claims of
  Sigstore conformance or public signer authorization.
- `S2-PRODUCTION-SIGSTORE` will use a release-specific A.M.Y manifest, genuine
  GitHub Actions keyless attestation, archived trusted root, Rekor evidence, and
  the pinned production adapter. It is not yet defined or executed.
- `S3-INDEPENDENT-REPRODUCTION` exists only if an external qualified reproducer
  later runs the complete released benchmark.

## Six structurally distinct S1 blueprints

| ID | Release kind | Distinguishing structure |
|---|---|---|
| `B01-TABULAR` | benchmark case | CSV data pair, code, nested JSON result, SVG, empty file |
| `B02-PAPER` | scientific paper | source, valid minimal PDF, evidence ledger, lock, result, figure |
| `B03-MODEL` | model artifact | deterministic binary model over two 1 MiB hash chunks, metadata, empty log |
| `B04-SOFTWARE` | software release | multiple nested source files, lock, configuration, duplicate-content pair |
| `B05-MODEL-EXCHANGE` | model exchange | exact authored request/response bytes and explicit opaque-backend limitation |
| `B06-MIXED-RESEARCH` | mixed research release | deep path, >1 MiB output, data, code, lock, ledger, manuscript |

Every byte is generated by a declared recipe under CC0-1.0; no historical
A.M.Y/ATLAS output or live provider response is copied into these bases. The
registry keeps its expected hashes `null` until R0 is independently reviewed and
frozen. Exploratory generated hashes live in the retained pilot summary instead.

## Draft compatibility matrices

`corpus/COMPATIBILITY_MATRIX_DRAFT.json` enumerates the full six-base ×
34-operator historical v0.3 product (204 candidate units): 174 compatible, 24
pending, and 6 structurally S2-only. It remains byte-identical because retained
pilot evidence binds it.

`corpus/COMPATIBILITY_MATRIX_SELECTED_PROFILE_DRAFT.json` is the current
selected-profile migration target. It enumerates six bases × 41 operators and is
derived from structural catalog fields, the selected prerequisite registry, and
the separately replayed clean-base run. It explicitly records that clean
base decisions are used only to establish fixture availability. It does not
read or store mutation outcomes, target decisions, or profile expectations.

Selected draft states:

| State | Units | Meaning |
|---|---:|---|
| `COMPATIBLE` | 185 | Every current structural prerequisite is true and the base-aware mutation target resolves |
| `PENDING` | 54 | No prerequisite is false, but one of five named policy-freeze prerequisites remains unresolved |
| `NOT_COMPATIBLE` | 7 | Six public-keyless transparency cases move to S2; `B04-SOFTWARE × INVENTORY-OMIT-ROLE-001` has no unique required-role target |

If all pending requirements become true, selected S1 would contain 239 planned
units and 956 paired profile rows per environment. Those are finite designed
units, not independent samples from a population and not a security-rate
denominator.

The selected validator recomputes every base-derived prerequisite, reconstructs
all 246 rows, and performs a counterfactual check: replacing every catalog
target decision and profile expectation with poisoned values leaves every row
unchanged. This supports outcome blindness for those declared fields; it is not
a proof against every possible covert information channel.

The matrix binds the exact deterministic plan for each resolvable row. Across
the full product, 245 plans resolve and one is unavailable. A separate
same-worktree development receipt executes 65 target-dependent plans only in
disposable copies, checks collision handling and forged-plan rejection, and
fixes every confirmatory, production, review, and manuscript boundary to false.

Hash-bound filesystem probes for both planned environments resolved 18
path-safety rows. Any relevant environment or probe-source change requires a
rerun before those prerequisites can remain true.
